# harness

## 说话方式（最高优先级）

只说能直接决定事情的话。说人话，不提脚本名、不提内部术语、不摆过程。全查完再一次说清，不让用户靠追问补全。汇报只有两种结论：**做到了 / 没做到**。

## 这套东西治什么

1. **边做边改**——上来就从细节开干，做到一半才发现方向错。正确顺序是先穷尽调查、列全问题、定死宏观战略、用户确认，然后才动手。
2. **凑形式验收**——"12 项全部通过""全绿""哈希一致"一出现，注意力就跑去满足形式。全砍。只剩真打开用一遍，行还是不行。
3. **前脚说完后脚忘**——用户上轮说的偏好，下轮开新会话就忘了。

## harness 是一个目录

在项目根目录建 `harness/`，七份文件，一份索引：

```
harness/
  总纲.md              索引，link 到下面各文件
  目标与原则.md        做成什么、什么不能违反
  用户偏好.md          用户原话。最高优先级
  战略步骤.md          现状、全部问题、宏观战略、复现步骤。顶部带确认状态
  路径与方法口径.md    能动的边界、方法口径、判断口径、改动范围
  动作与交互.md        按时间记谁说了什么、做了什么
  经验日记.md          每轮为什么改、改了啥、踩了什么坑；通病清单
```

**一类信息只有一个出处。** 按"动得勤不勤"分文件：偏好原则几乎不动，步骤日记天天动。

模板在同目录 `模板/`。用户喊"用我的harness"时项目里还没有，就照模板铺好。

## 阶段一：立战略（没确认不许写产物）

`harness/战略步骤.md` 顶部不是 `状态：已确认` 时，**不许写任何产物文件**。只能写 harness 目录自己的文档。

1. **穷尽调查**——相关的东西真读一遍。文件、数据、现状、约束。不抽查、不猜。
2. **列出全部问题**——结合实际情况列全。不筛、不删、不合并。难处理的更要写。
3. **找主干与配套**——哪个是主干，谁依赖谁，先做哪个。
4. **抽象宏观战略**——在什么目标和原则下，为了做什么，用什么方法，把什么做成什么样。
5. **用复现思路写战略步骤**——像老师教学生复现一个项目：
   - 第一步：在目标 X、原则 Y 下，为了做 Z，用方法 M 对材料 A，做成 B 样子
   - 第二步：基于已有的 B，用方法 N 做 C，达成 D 样子
   - 由重点到配套，由点成面。**是复现步骤，不是改错步骤。**
   - 每步写明：影响范围、怎么算做到了（使用者角度，不是检查项）
6. **跟用户确认**——确认后在 `战略步骤.md` 顶部写 `状态：已确认`

禁止为了让流程跑通而删变量、换问题、跳过难处理的地方。**沉默不等于同意。**

## 阶段二：执行

- 只按 `战略步骤.md` 走，不即兴加东西
- 动手前先看影响范围，只动该动的
- 每步做完，真实打开 / 运行 / 渲染成品
- 然后派一个上下文干净的智能体做对抗性审查（见下）
- 用户每说一句有用的话，**当场归档，不等这轮结束**

## 阶段三：判断与循环

每轮执行后必须真实打开、运行或渲染成品，再进入反馈循环：

```text
执行 → 真实验证 → 做到了？
                 ├─ 是：归档并结束
                 └─ 否：记下证据和根因 → 写经验 → 带具体修正进入下一轮
```

“没做到”不是结束语，而是下一轮的输入。下一轮必须带上上一轮的实际缺口、失败证据、原则和具体修正，不能只说“继续优化”。

验证无法执行、达到最大轮次、同一失败再次出现且成品没变、或目标方向发生变化时，进入阻塞并交给用户，不能假装完成，也不能无限重做。


**做到了 / 没做到。没有中间档。**

- 真实打开、运行或渲染，站最终使用者角度综合判断
- 不设分数、不列检查项数量、不摆指标
- 禁止出现：全绿、全部通过、测试通过、X 项通过、覆盖率、门禁、冻结
- 检查项只能发现问题，**不能定义完成**
- 发现问题先自己解释（设计如此？别处已处理？场景不适用？），解释不通才是真问题
- 判"没做到"就说清哪儿不行，直接改，只重查受影响范围

## 实时归档

用户每说一句有用的话，当场归档：

| 听到什么 | 记到哪 | 怎么记 |
|---|---|---|
| 要求 | `经验日记.md` | 他想解决什么问题、我该怎么改。一两句，口语化 |
| 偏好 | `用户偏好.md` | 用**他自己的说法**，别改意思 |
| 纠正 | `经验日记.md` 通病清单 | 我错在哪、根子上为什么错。只记新的 |
| 流水 | `动作与交互.md` | 原话 + 我干了什么 |

信号词：偏好——偏好/以后/永远/我不喜欢/我喜欢；纠正——错了/不对/跑偏/又忘/说人话/太啰嗦；要求——必须/禁止/应该/改成/我要。

## 对抗性审查

自己做完一轮之后才启动。**对抗性来自上下文隔离，不来自措辞。**

- 一次只给审查者：成品 + 一个具体问题
- 不告诉它前面查过什么、过了几项——知道"前面都过了"就会放水
- 每个问题在全新上下文里单独跑

## 改动范围

- 小改：只查受影响部分
- 动核心数据或核心方法：才全面重查
- 禁止小改就全盘重置

## 战略调整（唯一允许改方向的路）

1. 把问题提到战略口径（不是"这行不对"，是"这一步的方法在实际情况下不成立，因为…"）
2. 用战略口径跟用户确认
3. 确认后改 `战略步骤.md`，在「战略调整记录」补一条
4. 同时往 `经验日记.md` 记一条

**不另起新计划、不新建文件。**

## 通病清单（起始值，新发现追加）

套话 / 虚假精确 / 装饰性引用 / 结果与方法脱节 / 过度对称结构 / 占位符 / 猜测当事实 / 为跑通而简化掉难点 / 沉默当同意 / 用形式指标代替真实验收
