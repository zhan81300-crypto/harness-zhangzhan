# 张展nb666-Harness

给 Claude Code 装的插件。装上之后，AI 按一套硬规矩干活，绕不过去。

不改 Claude Code 本体一行代码。

---

## 治三个病

**一、边做边改。** AI 喜欢上来就从细节开干，做到一半才发现方向不对，然后反复返工。正确顺序是：先把现状查清楚，把问题列全，把宏观战略定死，你点头，然后才动手。这套东西用一道硬闸强制这个顺序——战略没你确认，它写不了产物。

**二、凑形式验收。** "12 项全部通过""哈希一致""全绿"——这些一存在，AI 的注意力就跑去满足形式，不去找真问题。全砍了。只剩一个判断标准：真打开用一遍，行还是不行。

**三、前脚说完后脚忘。** 你上轮说的偏好，下轮开新会话就忘了。你的偏好和原则自动存下来，每次会话开始时塞回它的上下文。

## 用

在任何项目里说 **"用我的harness"**，或者打 **`/harness`**。

它会照模板铺好 `harness/` 目录，然后开始阶段一：调查现状、列全部问题、抽象战略、写复现步骤，拿给你确认。**你确认之前它写不了产物。**

没铺 `harness/` 目录的项目，这套东西完全不生效，一点不打扰。

---

## harness 是一个目录

不是一个文档，是七份分文件，一份索引：

```
harness/
  总纲.md              索引，link 到下面各文件
  目标与原则.md        要做成什么、什么不能违反
  用户偏好.md          你说过的话。最高优先级，压过其他考虑
  战略步骤.md          现状、全部问题、宏观战略、复现步骤。顶部带确认状态
  路径与方法口径.md    能动的边界、方法口径、判断口径、改动范围
  动作与交互.md        按时间记 AI 干了什么、你说了什么
  经验日记.md          每轮为什么改、改了啥、踩了什么坑；通病清单
```

一类信息只有一个出处。按"动得勤不勤"分文件——偏好原则几乎不动，步骤日记天天动。

**战略步骤怎么写？** 像老师教学生复现一个项目：在什么目标和原则下，为了做什么，用什么方法对什么材料，做成什么样子；下一步基于已有的什么，再做什么。由重点到配套，由点成面。是复现步骤，不是改错步骤。

**要改方向只有一条路：** 把问题提到战略口径（不是"这行不对"，是"这一步的方法在实际情况下不成立，因为…"），跟你确认，然后改 `战略步骤.md` 本身。不另起新计划、不新建文件。

## 实时归档

这是最实用的部分。

你每说完一句话，闸门比 AI 先跑：原话按时间落进 `动作与交互.md`，这步是死的漏不掉。同时看你这句话里有没有要求、偏好、或者在纠它——有就当场给 AI 下指令：现在归档，别等。

AI 照着办：

- 你想干什么、要解决什么问题 → `经验日记.md`
- 你的偏好 → `用户偏好.md`（这份会自动塞回上下文）
- 你在纠它哪里错 → `经验日记.md` 的通病清单，记清根子上为什么错

这轮结束前该记的没记，收尾闸把它拦住，不让它结束。**不靠 AI 自觉，靠拦。**

做完一个项目你会得到：翻 `动作与交互.md`，看清自己提过哪些要求、AI 在哪跑偏、你怎么把它揪回来的；把 `经验日记.md` 单独给一个全新的 AI，它能照着从头复现最终版，路上所有坑都在里面。

## 两层设计

这套东西分两层，各自管各自的事：

| 层 | 机制 | 什么时候管用 |
|---|---|---|
| **硬闸**（地基） | 命令钩子 | 任何模式，包括无人值守 |
| **体验层**（增强） | mod | 交互会话 |

**为什么这么分？** 因为 mod 只在交互会话里生效，无人值守时全失效。而"战略没确认不许写产物"这道闸必须任何模式下都拦得住。所以硬闸用命令钩子做——那是被实战验证过的；mod 用来做体验——启动动画、输入框上面的实时状态条。

就算 mod 一次都没加载，硬闸照样管用。

---

## 四道闸在干什么

| 时机 | 干什么 |
|---|---|
| 你每说完一句话 | 落原话；认出要求/偏好/纠正就要求当场归档 |
| 新开会话、清屏、压缩上下文 | 把你的偏好和原则塞回它的上下文 |
| 它要写产物前 | 战略步骤没经你确认就拦住（含 Bash 绕道） |
| 这轮结束前 | 该记的没记，拦住；说完成没真判断，拦住 |

**没有 harness 目录的项目，四道闸一道都不触发。**

---

## 换 LLM 也不怕

规则本身是纯文本，在 `adapters/规则-通用.md`。任何能读写文件的 AI 都能照着做——把那份文件加进它的系统提示词就行。

`hooks-classic/` 和 `hooks/` 只是 Claude Code 上的适配器。换工具、换模型，规则那份不动。

## 对抗性审查

包里带一个上下文隔离的审查配置。AI 自己做完一轮后才调用它，**一次只给它成品加一个具体问题**，不告诉它前面查过什么、过了几项——知道"前面都过了"就会放水。

对抗性来自上下文隔离，不来自措辞。

```
types/                   类型契约

```
