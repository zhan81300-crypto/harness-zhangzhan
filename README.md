让 AI 围绕一份持续更新的项目总纲干活，把实际做事得到的经验留在里面，下一轮再用起来。 不是单纯记聊天，也不是给 AI 套一堆检查规则。

Harness 里装什么
它是一个可携带的项目文件夹，里面有一份总纲，串起整个项目：为什么做、最终做到什么样、不能违反什么、用户有什么偏好、采用什么方法和路径、按什么步骤复现、现在做到哪、试过什么、错在哪里、哪些方向被否决、最后固定下来的正确做法和模板。

不同内容分文件存，避免混乱，但它们共同构成一份完整交接资料。所有东西跟着这份 harness 走，不绑在某个人的账号或某个模型上。新 AI 接手后，不只是知道“最后答案是什么”，还知道“为什么这样做、哪些路不能再走”。

怎么围绕它干活
开工先调查实际情况，把问题、依赖关系和方法想清楚，整理成从头复现的战略步骤，交给用户确认。确认后，AI 按这份总纲执行，不随意换目标、换方法。遇到普通实现问题，直接修；发现战略本身不成立，先把原因讲清楚，经过用户确认再更新战略，不能偷偷改方向。

做完之后，独立审查员根据目标实际使用成品，主动找会让目标落空的地方。发现有效反证，就推翻“做到了”，退回修正。 不是检查动作做齐了就算完成。

Harness 怎么自更新
自更新不是不停追加文字，而是实际情况变化后，及时修正这份项目认识。

用户指出错误、提出偏好、否决方案时，系统当轮理解意思、保存原话，再按用户定的入册标准提炼。一次性细节留在流水；可复用原则、错误与纠正、被否方向及理由进入经验。新认识重复了就合并，补充了就完善，推翻了旧认识就明确保留否决理由，避免新旧说法同时生效。

执行和验收也会产生更新：这轮为什么失败、根因是什么、下一轮怎么改；真正做成以后，哪些方法可以固定下来。原则从案例里长出来，不能凭空编一套原则再强套案例。

下一轮，系统根据当前任务的意思找回相关经验，把它变成具体行动提醒。于是形成闭环：按总纲做事 → 从真实结果发现偏差 → 更新经验和做法 → 带着更新继续做。

靠什么实现，当前做到哪
程序通过 Claude Code、Codex 的钩子，在用户说话、会话开始、工具执行前和结束前接入；模型负责理解意思，程序负责写入、传递和阻断。固定时机由程序保证，内容取舍按用户标准由模型判断。

但必须纠正我前面的夸大：当前代码只实现了部分闭环，还没有实现上面完整的自更新。 已有原话保存、语义提炼、偏好与经验写入、召回、战略拦截和收尾审查；旧原则的自动合并与废止、失败经验自动沉淀、正确做法与模板定型、整份交接资料的持续整理，尚未完整接通。钩子也不是操作系统级隔离，不能承诺 AI 绝对绕不过去，更不能保证模型每次判断都正确。

你要的最终产品，是一份越做越有用、能传给下一个 AI 的项目经验；自动化引擎只是让它及时更新、真正参与行动的手段。
