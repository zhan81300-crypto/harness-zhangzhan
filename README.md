# 张展nb666-Harness

给 Claude Code 装的插件。让 AI 按一套硬规矩干活，绕不过去。

直接改 Claude Code 的运行逻辑——改它发给模型的系统提示词、拦它的工具调用、往它的上下文里塞东西。不是外挂，是动它的行为本身。

---

## 为什么要做这个

因为 AI 有三个毛病，光靠"跟它讲道理"治不好。

**一、边做边改。** 上来就从细节开干，做到一半才发现方向错，然后反复返工。你以为它想清楚了，其实它只想清楚了第一步。

**二、凑形式验收。** "12 项全部通过""哈希一致""全绿"——这些一出口，它的注意力就从"成品能不能用"跑到"指标好不好看"上了。检查项变成了交差的道具。

**三、前脚说完后脚忘。** 你上轮说的偏好，下轮开个新会话就没了。你每次都得重新说一遍。

这三个毛病的共同点：**规则写在提示词里，AI 可以听过就算。** 它不是不知道，是不照做，或者做着做着就漂了。

---

## 解决什么

把它说过的话，变成它绕不过去的约束。

- 战略没经你确认，**写不了产物**——不是"它记得不该写"，是工具调用被拦住。
- 说完成必须给判断，**用了形式指标会被拦**——不是"它知道不能说全绿"，是说了就过不去。
- 你每说一句有用的话，**当场归档**——不靠它自觉，靠拦。

---

## 怎么解决

**不是外挂一层壳，是直接改 Claude Code 的运行逻辑。** 具体动了它四处：

| 动的地方 | 怎么动的 | 效果 |
|---|---|---|
| **系统提示词** | 在它每次发给模型之前，追加一段规则 | AI 不是"被告知"规矩，是规矩成了它自己的设定 |
| **工具调用** | 在工具真正执行前拦下来 | 战略没确认时，写文件的操作物理上过不去 |
| **上下文** | 往模型眼前塞它自己看不到的内容 | 你说完一句话，归档指令当场就到了——你看不见，也不打断你 |
| **界面** | 在输入框上面画一条实时状态带 | 战略什么状态、归档了几笔，一眼看得见 |

落在项目里，就是四道闸卡在四个时间点上：

| 时机 | 闸门干什么 |
|---|---|
| 你每说完一句话 | 原话落进 `动作与交互.md`；认出要求/偏好/纠正，当场要求归档 |
| 新开会话、清屏、压缩上下文 | 把你的偏好、目标、通病清单塞回它的上下文 |
| 它要写产物前 | `战略步骤.md` 顶部不是「已确认」就拦住（含 `cat >`、`sed -i` 这类绕道） |
| 这轮结束前 | 该记的没记，拦住；说完成没给判断，拦住；用形式指标汇报，拦住 |

**为什么以前做不到。** 只能在外面拿钩子拦，拦不住 AI 的"想法"——它可以在回复里说"好的我现在就改"，你看见了，然后才被拦，体验是割裂的。Claude Code 新开的这套接口（Mods）把系统提示词、工具调用、会话上下文、界面绘制都开放出来了，才能改它的设定本身。

**两个关键取舍：**

**闸门分两层。** 硬闸用命令钩子做——任何模式都生效，包括无人值守；体验层用 mod 做——启动动画、状态条，只在交互会话里生效。mod 一次都不加载，硬闸照常管用。

**规则和机制分家。** 规则全文在 `adapters/规则-通用.md`，纯文本，任何能读写文件的 AI 都能照着做。上面那四处接口只是 Claude Code 上的适配器——换模型、换工具，规则那份不动。

## 特别在哪

**它不新增一套流程，它逼你先把话说清楚。**

装完之后你在项目里说一句"用我的harness"，它会照模板铺好 `harness/` 目录——七份文件，一份索引：

```
总纲.md              索引
目标与原则.md        做成什么、什么不能违反
用户偏好.md          你说过的话。最高优先级
战略步骤.md          现状、全部问题、宏观战略、复现步骤
路径与方法口径.md    能动的边界、方法口径、判断口径
动作与交互.md        按时间记谁说了什么、做了什么
经验日记.md          每轮为什么改、改了啥、踩了什么坑
```

然后它走阶段一：穷尽调查 → 列全部问题 → 分主干配套 → 抽象宏观战略 → 用复现思路写战略步骤 → 拿给你确认。

**像老师教学生复现一个项目**：在什么目标和原则下，为了做什么，用什么方法对什么材料，做成什么样子；下一步基于已有的什么，再做什么。由重点到配套，由点成面。是复现步骤，不是改错步骤。

你点头之前，它写不了任何产物。

**要改方向只有一条路**：把问题提到战略口径（不是"这行不对"，是"这一步的方法在实际情况下不成立，因为…"），跟你确认，然后改 `战略步骤.md` 本身。不另起新计划、不新建文件。你的项目不会攒出八个版本的垃圾。

**做完一个项目你会得到两样东西：**

翻 `动作与交互.md`，看清自己提过哪些要求、AI 在哪跑偏、你怎么把它揪回来的。

把 `经验日记.md` 单独给一个全新的 AI，它能照着从头复现最终版，路上所有坑都在里面。

**这是这套东西真正的价值。** 你今天不知道明天会踩什么坑——没人知道，除非真做过。但踩过之后，坑被记下来了。下次谁来做，不用再踩一遍。

## 装

需要 Python 3。

**插件市场：**

```
/plugin marketplace add zhan81300-crypto/harness-zhangzhan
/plugin install harness
```

**手动：**

```bash
git clone https://github.com/zhan81300-crypto/harness-zhangzhan
cd harness-zhangzhan
python 安装.py
```

卸载：`python 安装.py 卸载`

**没铺 `harness/` 目录的项目，四道闸一道都不触发，一点不打扰。**

## 自测

```bash
python 自测.py
```

拿真实输入跑四个入口，看该拦的拦不拦、该记的记不记、不误伤正常对话、不把自己锁死。24 项。

---

## 对抗性审查

包里带一个上下文隔离的审查员。自己做完一轮之后才调用，**一次只给它成品加一个具体问题**，不告诉它前面查过什么、过了几项——知道"前面都过了"就会放水。

对抗性来自上下文隔离，不来自措辞。
